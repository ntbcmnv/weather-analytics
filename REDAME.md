# Weather Analytics

Интерактивная погодная аналитика для Кыргызстана: карта, переключаемые погодные слои и временной график.

# Установка зависимостей

```
npm install
```

# Запуск dev-сервера

```
npm run dev
```

# Проверка TypeScript и production-сборка

```
npm run build
```

# Локальный просмотр production-сборки

```
npm run preview
```

# Возможности

- Карта на MapLibre GL.
- Слои: температура (°C), ветер (м/с), солнечная радиация (Вт/м²).
- Timeline синхронизирован с картой и графиком Recharts.
- Данные загружаются из Open-Meteo Forecast API.
- Общее состояние приложения хранится в Vedro.
- Для показателя солнечной радиации используется shortwave_radiation из Open-Meteo.

# Технологии

- React 
- TypeScript 
- Vite 
- Tailwind CSS  
- Vedro  
- MapLibre GL  
- Recharts 
- Open-Meteo API

**MapLibre GL** выбран за интерактивность, гибкую стилизацию и контроль над картографическими слоями. Для графиков используется Recharts.

# Состояние и синхронизация

Vedro хранит активные слои, набор данных, выбранную локацию и статус загрузки. Timeline обновляет общий selectedTimeIndex; карта показывает значения для выбранного времени, а Recharts отображает временной ряд выбранной локации и выделяет соответствующий момент.

# Архитектура и границы ответственности

Проект использует модульный подход с элементами Feature-Sliced Design (FSD):

- **app** — инициализация приложения, провайдеры и глобальное состояние.
- **entities** — погодные сущности, типы и конфигурация слоёв.
- **features** — пользовательские действия: переключение слоёв и управление временем.
- **modules/map** — отображение данных на карте MapLibre GL.
- **modules/analytics** — временные ряды и графики Recharts.
- **modules/data-access** — получение погодных данных из API.
- **shared** — общие UI-компоненты и утилиты.

Такое разделение позволяет изменять визуализацию, работу с данными и пользовательские сценарии независимо друг от друга.

# Производительность и масштабирование

Для уменьшения лишней нагрузки используются ленивый импорт карты и графика, а также отмена устаревших запросов при повторной загрузке данных.

# Компромиссы

Для тестового задания выбран Open-Meteo API и ограниченный набор погодных показателей. Это позволяет продемонстрировать работу с временными рядами, картой и синхронизацией интерфейса без построения полноценной GIS-платформы.

Серверная обработка пространственных данных и сложная оптимизация больших наборов данных оставлены за пределами текущей реализации.
